# 앱 반영 목록

시안 버전마다 **앱에 고쳐야 할 것**을 빠짐없이 적는다. 맨 위가 최신 버전이다.

- 기준은 **출시된 앱**이다(지금 iOS 1.2.1). 아직 앱에 안 들어간 버전은 아래 버전부터 차례로 반영한다.
- 같은 화면을 뒤 버전이 다시 고쳤으면 뒤 버전 값이 이긴다. 그 항목에는 「→ 1.x에서 바뀜」이라고 적어 둔다.
- 앱에 반영하면 그 버전 제목 옆 상태를 「반영됨 (iOS x.y.z)」로 바꾼다.
- 문구는 한국어가 정본이다. 시안은 한국어만 본다. 앱 문자열 키가 영어라서 **영어 값은 앱에 반영할 때 한국어 뜻에 맞춰 같이 고친다** — 따로 정해 주지 않는다.
- 항목 하나 = 시안 화면 id · 지금 앱(AS-IS) · 바꿀 값(TO-BE) · 앱 위치.

### 광고성 알림 노출 규칙 — 정본 (2026-11-17)

**기준은 화면 설계서 + 아래 결정이다.** Figma 「00. 화면 플로우」는 설계서와 부딪히는 곳이 있어 참고만 한다(부딪히면 이 절이 이긴다).

**광고성 정보 3종 — 전부 광고성 동의가 있어야 발송**
- 이번 주 특집(큐레이션) — 직접 고른 세트
- 좋아요한 아티스트의 신곡 — 그 아티스트 신곡이 나오면
- 이번 주 추천 — 좋아요한 곡 기반(앱 업데이트 소식은 「매주 월요일 5곡」, 설계서 배지는 「최대 10곡」 — 곡 수는 서버가 정하고 배지 m은 실제 곡 수)
- 발송 조건: 광고성 동의 true + 기기 알림 권한 허용. 21시~다음 날 08시엔 **야간 동의**도 true여야 한다(설계서 야간 토글 설명 기준 신곡·특집. 주간 추천은 낮 발송이라 무관). 야간 동의가 없으면 그 시간엔 보내지 않는다(08시 이후로 미룰지 건너뛸지는 서버가 정한다)

**동의를 묻는 곳 3곳 + 설정 1곳**
- **A. 첫 실행 동의 팝업**(Popup `row`, 「좋아하는 (아티스트)의 신곡, 바로 알려드릴까요?」)
  - 언제: 신규 유저 = 피드 코치마크를 끝낸 직후. 기존 유저 = 업데이트 후 첫 실행에서 업데이트 소식(새로운 기능) 시트를 닫은 직후
  - 조건: 로그인 · 광고성 동의 미응답 · **좋아요한 곡 1곡 이상**(아티스트 = 가장 최근 좋아요한 곡의 아티스트. 신규 유저는 코치마크 좋아요가 있어 항상 만족) · 7일 안에 띄운 적 없음. 게스트는 묻지 않고 로그인 뒤 다음 실행에서
  - 알림 받기 → 광고성 동의 true 저장 → 기기 권한 「설정 전」이면 OS 권한 팝업 → 결과 토스트(수신동의). 이미 허용·거부면 토스트만(설정 앱을 자동으로 열지 않는다 — 꺼져 있으면 마이 › 알림 「기기 알림 권한 · 꺼짐」에서 켠다)
  - 나중에 → **닫기만**(저장·통지 없음). 7일 뒤 같은 조건이면 다시
- **B. 좋아요 시점 신곡 알림 시트**(ConsentSheet, 「(아티스트) 신곡 소식을 받아보세요!」)
  - 언제: 피드에서 곡을 좋아요하고 **다음 곡으로 넘긴 직후**(픽 재생·잠금화면 좋아요 제외)
  - 조건: 로그인 · 기기 알림 권한 「설정 전」 · 실행 2회 이상 · 7일 안에 「일주일 동안 안 보기」 안 누름 · 로그인 시트·리뷰 요청·업데이트 소식·트랙 상세가 안 떠 있음
  - 알림 받기 → 광고성 동의 true + OS 권한 팝업 → 결과 토스트. 일주일 동안 안 보기 → 닫기만, 7일 뒤 같은 동작에서 다시
- **C. 야간 동의 팝업**(Popup `row`, 「밤에도 아티스트 소식을 알려드릴까요?」)
  - 언제: 이번 주 특집 마지막 곡(5/5)을 넘긴 직후, 다음 곡 위에
  - 조건: 광고성 동의 true · 기기 권한 허용 · 야간 동의 미응답
  - 알림 받기 → 야간 true + 토스트 / 아니요 → 야간 false + 토스트(둘 다 응답이라 다시 묻지 않는다 — 바꾸려면 마이 › 알림)
- **D. 마이 › 알림**(언제든) — 광고성·야간 토글, 기기 알림 권한. 규칙은 항목 10

**세션(앱 실행 1회) 규칙**
- A·B·C는 **한 실행에 하나만**. 기존 권한·제안 팝업(리뷰 요청·픽 올림 알림 권유)과 같은 「이번 실행에 띄움」 플래그를 쓴다(1.3.2 `AppSession.didShowPermissionPopup`)
- 이번 실행에서 광고성 동의를 받았으면 C(야간)는 다음 실행부터
- 우선순위(한 실행에 둘 이상 조건이 맞으면): A → B → C
- 동의 팝업·시트는 **버튼으로만 닫힌다**(딤·바깥 탭 무반응). 버튼은 팝업만 닫고 피드 곡은 그대로

**공통**
- 결과 통지 = 토스트(항목 6), 날짜는 서버 처리일. 전송자 「Dignify의」 포함
- 동의 문구: A·B·C 모두 「'알림 받기'를 누르면 (야간) 광고성 정보 수신에 동의해요.」를 화면에 둔다(B 시트는 설계서에 없어 추가 — 기획 확인 대기)
- 야간 시간 문구는 설계서 그대로 「오전 8:00 ~ 오후9:00」(실제 야간은 21시~08시라 반대로 보인다 — 기획 확인 대기)
- 7일 기준은 기기 기록(마지막으로 띄운 시각). 미응답/응답은 서버 값(`adPushConsentAt` null = 미응답)
