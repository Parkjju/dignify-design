# 시안 수정하기

이 사이트는 세 층이 서로 연결돼 있다. **토큰 → 컴포넌트 → 화면 → 흐름.** 아래 층을 고치면 위 층이 전부 따라 바뀐다.

- **Foundations** — 색·글꼴·여백. 바꾸면 모든 컴포넌트가 바뀐다.
- **Components** — 버튼·카드 같은 부품. 바꾸면 그 부품을 쓰는 모든 화면이 바뀐다.
- **Screens** — 부품을 조립한 앱 화면. 화면마다 Controls로 내용·상태를 바꿔 볼 수 있다.
- **Flows** — 화면을 순서대로 놓은 흐름. Controls의 `steps`로 순서를 바꿔 볼 수 있다.

## 1. 바로 바꿔 보기 — Controls (저장 안 됨)

화면이나 컴포넌트를 열고 아래 **Controls** 탭에서 값을 바꾼다.

- 곡(`track`): 목록에서 고른다. 제목·문구: 그대로 입력한다.
- 상태(`hyped`, `locked`, `editing`, `sheet` …): 켜고 끈다.
- `scroll`: 긴 화면의 아래쪽을 본다.
- 목록(`picks`, `crateDays`, `steps` …): JSON을 직접 고친다. 항목을 지우거나 복사해서 늘린다.

바꾼 값은 저장되지 않는다. 새로고침하면 원래대로 돌아간다. 남기고 싶으면 아래 3번처럼 요청한다.

## 2. 흐름 설계 — Flows

1. 왼쪽 **Flows**에서 가까운 흐름을 연다(첫 실행, 픽 만들기 …).
2. Controls의 `steps`를 고친다. 한 칸은 이렇게 생겼다.

```json
{ "screen": "feed", "label": "하입", "note": "더블탭 또는 삽 버튼", "args": { "hyped": true } }
```

   - `screen` — 화면 id. 쓸 수 있는 id는 Controls의 `steps` 설명에 다 있다.
   - `label`, `note` — 카드 아래 이름과 설명.
   - `args` — 그 칸에서만 바꿀 값. 화면 Controls에 보이는 이름과 같다.
3. 순서를 바꾸려면 칸을 잘라 붙이고, 칸을 늘리려면 복사한다.
4. 마음에 들면 `steps` JSON을 통째로 복사해서 Claude에게 넘긴다. "이 흐름을 Flows에 '○○'로 저장해줘."

**없는 화면이 필요하면** `screen`에 지어낸 id를 넣는다. 빨간 점선 칸으로 표시된다. 그 칸이 곧 "새로 만들 화면" 목록이다.

## 3. 시안 고치기 — Claude에게 요청

화면 배치나 흐름을 정했으면 Claude에게 말로 넘긴다. 요청에 이 셋이 들어가면 한 번에 맞는다.

- **어디를** — 화면 이름 또는 id(`digging-profile`), 흐름 이름. 스크린샷에 표시해서 붙여도 된다.
- **무엇을** — 넣기·빼기·순서 바꾸기·문구, 그리고 상태(빈 상태, 로딩, 에러)도 필요한지.
- **왜** — 한 줄. 판단이 갈릴 때 기준이 된다.

예시:

- "디깅 프로필에서 '주요 아티스트'를 '내가 만든 픽' 아래로 내려줘. 처음 보는 사람이 픽부터 보게 하려고."
- "Flows '픽 만들기'에 곡 고르기 다음 '미리듣기 화면'을 넣고 싶어. 새 화면이니까 컴포넌트부터 제안해줘."
- "피드 칩 문구를 '○○를 좋아하면'으로 바꾸는 시안. 앱 문구랑 같이 바뀌어야 해."

Claude는 이렇게 처리한다.

1. 앱 코드에서 지금 값을 확인한다.
2. 기존 컴포넌트로 조립한다. 없으면 컴포넌트를 먼저 만든다(명세 · 마크업 · 스타일 · 스토리).
3. 렌더해서 확인하고 PR을 올린다.
4. 머지되면 이 사이트에 자동 반영된다. 링크를 공유해서 리뷰한다.

## 4. 직접 고치기 (코드가 편하면)

- **화면 배치** — `screens/<흐름>.js`의 화면 함수. 컴포넌트 호출이 위에서 아래 순서대로 놓여 있다. 줄 순서를 바꾸면 화면 순서가 바뀐다.
- **화면 기본값** — `screens/registry.js`. 화면마다 기본 args가 한 줄씩 있다.
- **흐름** — `flows/flows.stories.js`. 흐름 하나가 `steps` 배열 하나다.
- **부품 모양** — `components/<이름>/<이름>.css`. 모든 화면에 반영된다.
- **색·크기** — `tokens/*.json`. 그다음 `npm run tokens`를 실행한다. iOS·Android 코드도 같이 생성된다.

로컬에서 보려면 `npm run dev`를 실행하고 http://localhost:6006 을 연다. 저장하면 바로 반영된다.

## 5. 휴대폰에서 보기 (실기기 모드)

휴대폰에서 **`/m.html`** 을 연다(로컬은 `npm run dev` 출력의 「On your network」 주소 + `/m.html`, 맥과 같은 와이파이). 목록에서 고르면 기기 테두리 없이 화면 가득 열린다.

- **직접 해 보기** — 코치마크를 실제로 조작한다. 더블탭 → 아무 곳 탭 → 위로 쓸기. 끝나면 피드처럼 계속 넘기고 더블탭으로 하입한다.
- **흐름** — 한 장씩 넘긴다. 오른쪽 탭 = 다음, 왼쪽 1/4 탭 = 이전.
- **길게 누르면(0.8초) 목록으로** 돌아간다.
- 가짜 상태바는 목록 맨 위 스위치로 켜고 끈다.
- Safari 공유 › **홈 화면에 추가**로 `/m.html`을 저장하면 주소창 없이 앱처럼 열린다.

데스크톱에서는 툴바의 **실기기**·**상태바** 메뉴로 같은 모드를 켤 수 있다.

## 지키는 것

- **새 값은 토큰으로 넣는다.** 화면에서 바로 hex나 px를 쓰지 않는다.
- **앱과 다르게 생긴 시안은 소통에 못 쓴다.** 앱에 이미 있는 화면을 고칠 때는 앱 코드의 값부터 맞춘다.
- **시안이 확정되면 앱 반영은 별도 작업이다.** 토큰은 생성물을 복사하고, 컴포넌트는 명세의 플랫폼 표를 보고 iOS·Android에서 구현한다.
